# 4.6 按供应商选择模型

v3.20.0 起，本地代理在**接管 Codex / Claude 之后**会把各张参与路由的供应商卡合并进选择器。用带前缀的模型 id 发请求时，代理会**钉到那张卡**，不再走跨卡故障转移。

> 前提：先按 [4.1 代理服务](./4.1-service.md) 启动代理，再按 [4.2 应用接管](./4.2-routing.md) 打开 Codex 和/或 Claude 接管。未接管时，CLI 仍直连当前供应商，看不到合并目录。

相关界面：代理面板顶部的接管提示、供应商添加/编辑页的「路由 slug」和「参与路由目录」。

## 先看一次完整流程

1. 添加至少一张会参与路由的供应商卡（API Key 卡，或认证中心绑定的托管卡）。
2. 启动代理，打开 **Codex** 或 **Claude** 接管。
3. 在 CLI 里选带前缀的模型 id（见下表）。
4. 需要固定某张卡时用 `{slug}/{model}`；需要多账号自动选闲号时，对官方族模型**不要**加 slug 前缀。

| 应用 | 选择器里看到的 id | CLI 示例 |
|------|-------------------|----------|
| Codex | `{slug}/{model}` | `codex -m "kimi/k2" "解释这段代码"` |
| Claude Code | `anthropic/{slug}/{model}` | `claude --model "anthropic/kimi/k2"` |
| Claude Desktop | `{slug}/{model}` | 在模型列表里选合并后的条目 |

Claude Code 接管后会打开网关模型发现（`CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY=1`）。`/model` 从本地 `GET /v1/models` 拉列表。Claude Code 会过滤不含 `claude` / `anthropic` 的 id，所以目录写成 `anthropic/{slug}/{model}`。haiku / sonnet / opus / fable 角色别名不变。

Claude Desktop 的 `/claude-desktop/v1/models` 继续返回合并后的 `slug/model` 列表，与 Claude Code 的 `anthropic/...` 目录分开，互不混用。

## 钉选一张卡：`{slug}/{model}`

规范 id 是 `{routing_slug}/{upstream_model}`。

- 请求带上这个 id 时，代理固定打到对应供应商卡，并注入该卡绑定的凭据。
- 即使 Codex 当前登录的是另一个 ChatGPT 账号，`main/gpt-5.5` 仍钉选 `main` 这张卡并注入该卡 token。
- 钉选后**不会**再走应用级跨卡故障转移。

### 路由 slug 从哪来

在供应商的添加/编辑页可以看到 **路由 slug**：

- 留空：优先用供应商 `id`，否则由名称生成。
- 建议保存一个覆盖值（例如 `kimi`、`deepseek`），避免以后改名把旧会话打到别的卡。
- 卡片上会显示「路由 {slug}」徽章。

同一页还有 **参与路由目录** 开关：

- 默认开启：该卡模型出现在 Codex / Claude Desktop 的合并列表里。
- 关闭：选择器里不再列出这张卡，但仍可用 slug 前缀直接请求。

也可以在代理面板的 **参与路由的配置** 里按卡勾选，不必一张张打开编辑页。平台开关（Codex / Claude / …）只决定要不要接管该应用的 live 配置，不会替你挑选哪几张卡进选择器。Gemini / Grok 没有合并目录，仍用当前配置 + 故障转移队列。

表单会预览「将写入目录」的若干条 id，方便对照。

### 上游模型 id 里有 `/`

上游模型 id 内部若含 `/`，目录里会写成 `-`。例如 `org/model` → `kimi/org-model`。两种写法请求都认。

### 第一段不是已配置的 slug

例如 Claude Desktop 自带的 `anthropic/claude-sonnet-5`：第一段 `anthropic` 不是某张卡的路由 slug 时，代理会回落到当前供应商，而不是返回 400。

## 未加前缀：当前供应商，或账号池

不带 slug 前缀的模型名保持原行为：走当前供应商；若开启了应用级故障转移，仍按队列切换。Claude 仍可用 haiku / sonnet / opus / fable 角色别名。

下面三类**官方族**在「同一应用下有两张及以上同族卡、且请求未加前缀」时，改为走**账号池**，而不是只打当前启用卡：

| 账号族 | 未加前缀时会进池的模型 | 用量来源 |
|--------|------------------------|----------|
| ChatGPT Official（Codex 官方卡） | `gpt-*`、`o1` / `o3` / `o4*`、`codex-*` | 卡片订阅查询 |
| Kimi For Coding（托管 OAuth 卡） | `kimi-for-coding`、`k2`、`k3` | 该卡套餐查询 |
| Claude Pro/Max（存有 `sk-ant-oat…` 的 OAuth 卡） | `claude-*` | 该账号配额查询 |

账号池规则：

1. **选闲号**：新会话选已知用量**最低**的账号。用量未知的账号排在后面，不会被当成 0%。
2. **会话粘性**：对话粘在开启该会话的账号上。
3. **何时换号**：该账号返回 401 / 403 / 429，或最热窗口用量 ≥ 80% 且池里有更闲的账号。换号发生在**下一轮请求**，不会在同一请求里中途换卡。
4. **钉选优先**：`{slug}/模型` 仍然钉卡，不走池。
5. **Official ChatGPT**：同一请求内不会跨账号故障转移。某一跳失败就失败，不会立刻拿另一张官方卡重试这一跳。

用量来自卡片底部的订阅/套餐查询，以及成功转发后最多每 60 秒一次的后台刷新。认证中心也会显示对应账号的用量。托盘菜单**不会**为 Kimi / Anthropic 托管账号展示配额摘要。

## 托管登录卡怎么接到路由上

token **不会**写进供应商卡片，只存在本机 account store。完整登录步骤见 [1.5 个性化配置 → OAuth 认证中心](../1-getting-started/1.5-settings.md#oauth-认证中心beta) 和 [2.1 添加供应商 → 托管 OAuth 供应商](../2-providers/2.1-add.md#托管-oauth-供应商kimi--claude-promax)。

简要步骤：

1. 设置 → **OAuth 认证中心**：登录 Kimi（设备码）或 Claude Pro/Max（浏览器 PKCE / 导入 Claude CLI）。
2. 添加供应商，选预设 **Kimi For Coding (OAuth)** 或 **Claude Pro/Max (OAuth)**，绑定刚才的账号。
3. 启动代理并接管后，选择器会出现 `{slug}/{model}`；未加前缀的官方族 id 在多卡时走账号池。

> 空的「Claude 官方」种子卡（未完成登录、没有 OAuth token）**不能**当作代理可用的 Claude Pro/Max 卡。请用认证中心登录后再绑定预设。

## 常见用法

**只想用某一张中转卡的某个模型**

```bash
codex -m "packy/claude-sonnet-4-6"
claude --model "anthropic/kimi/kimi-for-coding"
```

**多张官方 ChatGPT 卡，让新对话自动去闲号**

在 Codex 里继续用未加前缀的 `gpt-5.5`（不要写成 `main/gpt-5.5`）。需要锁死某张卡时再加 slug。

**不想让某张测试卡出现在选择器里**

编辑该卡，关闭「参与路由目录」，需要时仍可用 `testdev/k2` 直接请求。

**跨卡故障转移或加权轮询**

不要依赖「钉选 id + 应用级故障转移」。改用 [4.7 Combo 虚拟模型](./4.7-combo.md) 的 `combo/{id}`。

## Codex 选择器里的目录从哪来

`~/.codex/cc-switch-model-catalog.json` 是接管后的静态投影，**不是**上游 `/v1/models` 的实时镜像。每张 Codex 卡会合并：

1. 卡片映射表（保留你填的显示名、上下文窗口）
2. 该卡 `config.toml` 里的 `model =` 以及 `[model_providers.*].models`
3. 官方 ChatGPT 卡的本地种子（`gpt-5.4` / `gpt-5.5` / `gpt-5.6*` 等），不现场去拉 chatgpt.com
4. 上次成功的上游 `GET /v1/models`（写在 `~/.codex/cc-switch-model-discovery.json`）

回环地址（本机代理 `127.0.0.1` / `localhost`）和 `PROXY_MANAGED` 占位 Key **不会**被拿去拉列表，避免打回本地代理自己。第三方卡要出现在选择器里，必须加在 **Codex** 页，不是 Claude 页。

打开或再次确认 Codex 接管、保存 Combo 后，CC Switch 会重写投影并尝试补拉一次。**必须完全退出并重启 Codex**，`/model` 才会读到新文件。oh-my-codex 的 `omx setup` 可能改掉 `model_catalog_json`，请保持它指向 `cc-switch-model-catalog.json`。

## 注意事项

- 不需要、也不应再单独启动 OpenCodex / `ocx`。路由由本机代理完成。
- 供应商 slug **不要**取名 `combo`：有 Combo 时 `combo/` 命名空间已被占用，见 [4.7](./4.7-combo.md)。
- 裸 `gpt-*` 不会从选择器里隐藏；未加前缀时按上面的账号池规则处理。
- 改 slug 后，旧会话里写死的 `{旧slug}/{model}` 不会自动跟着改，建议改名前先记下覆盖值。
