# 4.7 Combo 虚拟模型

Combo 把一组真实的 `供应商slug/模型` 收成一个虚拟模型 `combo/{id}`。请求这个 id 时，代理按策略在目标之间转发，**不依赖**应用级故障转移开关。

> 前提：代理已启动，且已接管要使用的应用（Codex 和/或 Claude）。目标里的 slug 必须是当前应用下已有的路由 slug。钉选单卡请用 [4.6 按供应商选择模型](./4.6-model-routing.md)，不要建只有一个目标的 Combo。

## 在哪里配置

主界面打开 **Proxy** 面板（代理运行中），向下找到 **Combo 虚拟模型**。

需要填写：

| 字段 | 说明 |
|------|------|
| Combo id | 短名，例如 `main`。请求时写成 `combo/main` |
| 策略 | `failover` 或 `round-robin` |
| 目标 | 每行一个 `provider/model`，可选 `:weight` |

保存后列表里会显示 `combo/{id}`、策略和目标摘要。点击一条可改，垃圾桶删除。

## 目标怎么写

每行一个目标，也可用逗号分隔：

```
kimi/k2
deepseek/deepseek-v4:1
packy/claude-sonnet-4-6:2
```

- 基本形式：`{routing_slug}/{upstream_model}`
- 带权重：`{routing_slug}/{upstream_model}:{正整数}`。省略时权重为 1
- slug 必须能解析到当前应用下的一张卡；模型名是该卡的上游模型 id

## 两种策略

### failover（默认）

按配置顺序尝试。某一跳可重试失败后换下一个目标。整条 Combo 路径自己完成切换，不必打开 [4.3 故障转移](./4.3-failover.md) 的应用级开关。

适合：主用一张便宜/快的卡，失败再落到更稳的卡。

### round-robin

按权重平滑选择**第一跳**。第一跳失败后仍会继续尝试列表里其余目标。

适合：几张能力接近的卡分担流量。权重大的被选为第一跳的次数更多。

## 在 CLI 里怎么用

```bash
codex -m "combo/main" "解释这段代码"
claude --model "anthropic/combo/main"
```

Claude Code 选择器里的 id 是 `anthropic/combo/{id}`，与普通钉选一样带 `anthropic/` 前缀。

## 失败时返回什么

| 情况 | HTTP | 含义 |
|------|------|------|
| 没有叫这个名字的 Combo | 400 | 例如写了 `combo/foo` 但只保存过 `combo/main` |
| Combo 存在，但当前应用下没有任何目标能解析到卡 | 503 | slug 写错、卡被删、或接管的是另一个应用 |

应用级故障转移队列**不会**接过这两个错误再换供应商。要换目标，把备用卡写进 Combo 目标列表。

## 和钉选、账号池、应用级故障转移的区别

| 写法 | 行为 |
|------|------|
| `kimi/k2` | 钉死 Kimi 那张卡 |
| `gpt-5.5`（未加前缀，多张官方卡） | 账号池选闲号，会话粘性 |
| `combo/main` | 按 Combo 策略在多张卡的指定模型之间走 |
| 未加前缀 + 打开应用级故障转移 | 当前供应商失败后按队列换**整张卡**（该卡默认模型） |

同一请求里：钉选优先于账号池；`combo/` 走 Combo，不再当作品牌名。

## 注意事项

- 有任意一条 Combo 时，`combo/` 命名空间被占用。供应商的路由 slug **不要**写成 `combo`。
- 目标必须是 `slug/model`，不要写成 `anthropic/kimi/k2`（那是 Claude Code 选择器里的展示 id）。
- 改卡的 slug 后，Combo 目标不会自动改写，需要打开代理面板改目标行。
- Combo 不会替你登录。目标卡若是托管 OAuth，仍需先在认证中心登录并绑定。
