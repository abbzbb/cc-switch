# 4.6 プロバイダーでモデルを選ぶ

v3.20.0 以降、**Codex / Claude を接管**すると、ローカルプロキシは参加中のカードをセレクタにまとめます。接頭辞付きのモデル id で送ると、そのカードに**固定**され、カード横断のフェイルオーバーは行いません。

> 先に [4.1](./4.1-service.md) でプロキシを起動し、[4.2](./4.2-routing.md) で Codex / Claude 接管をオンにしてください。接管していないと CLI は現行プロバイダーへ直結し、結合カタログは見えません。

プロキシパネルのヒント、および追加/編集画面の「ルーティング slug」「ルーティングカタログに含める」も使います。

## 手順

1. ルーティングに参加するカードを少なくとも 1 枚追加する（API Key、または認証センターでバインドしたマネージドカード）。
2. プロキシを起動し、**Codex** または **Claude** 接管をオンにする。
3. 下表の接頭辞付き id を CLI で指定する。
4. カードを固定するときは `{slug}/{model}`。公式系モデルで空きアカウントを自動選択するときは slug を**付けない**。

| アプリ | セレクタ上の id | 例 |
|--------|-----------------|----|
| Codex | `{slug}/{model}` | `codex -m "kimi/k2" "このコードを説明して"` |
| Claude Code | `anthropic/{slug}/{model}` | `claude --model "anthropic/kimi/k2"` |
| Claude Desktop | `{slug}/{model}` | 結合リストから選ぶ |

Claude Code 接管時はゲートウェイモデル発見がオンになります（`CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY=1`）。`/model` はローカル `GET /v1/models` を読みます。`claude` / `anthropic` を含まない id は捨てられるため、カタログは `anthropic/{slug}/{model}` です。haiku / sonnet / opus / fable の役割エイリアスは変わりません。

Claude Desktop の `/claude-desktop/v1/models` は結合済み `slug/model` を返します。Claude Code の `anthropic/...` カタログとは別物です。

## カード固定：`{slug}/{model}`

正規 id は `{routing_slug}/{upstream_model}` です。

- この id のリクエストはそのカードへ固定され、そのカードの認証情報が注入されます。
- Codex が別の ChatGPT アカウントでログイン中でも、`main/gpt-5.5` は `main` カードを固定し、そのトークンを注入します。
- 固定リクエストはアプリ級のカード横断フェイルオーバーを使いません。

### slug の出所

追加/編集フォームの **ルーティング slug**：

- 空欄：プロバイダー `id`、なければ名前から生成。
- 上書き値（`kimi` など）を保存すると、後から改名しても古いセッションが別カードへ飛びません。
- カードに「ルーティング {slug}」バッジが出ます。

**ルーティングカタログに含める**：

- オン（既定）：Codex / Claude Desktop の結合リストに出ます。
- オフ：リストには出ませんが、slug 接頭辞での直接指定はできます。

プロキシパネルの **ルーティングに含める設定** でもカード単位で選べます。プラットフォームスイッチは live 設定を引き継ぐかどうかだけです。Gemini / Grok に結合カタログはなく、現行設定とフェイルオーバーキューを使います。

フォームはカタログに書き込む id の一部をプレビューします。

### 上流モデル id に `/` があるとき

カタログでは `/` を `-` にします（`org/model` → `kimi/org-model`）。リクエストはどちらも受け付けます。

### 先頭が設定済み slug でないとき

例：Claude Desktop の `anthropic/claude-sonnet-5`。先頭の `anthropic` がどのカードの slug でもない場合、400 ではなく現行プロバイダーへフォールスルーします。

## 接頭辞なし：現行プロバイダー、またはアカウントプール

slug なしのモデル名は従来どおり現行プロバイダーへ行きます。アプリ級フェイルオーバーがオンならキューに従います。Claude の役割エイリアスもそのままです。

次の公式系は、同じアプリに同族カードが 2 枚以上あり、かつ接頭辞なしのとき **アカウントプール** になります。

| 系統 | プールに入る接頭辞なし id | 使用量の出所 |
|------|---------------------------|--------------|
| ChatGPT Official（Codex 公式カード） | `gpt-*`、`o1` / `o3` / `o4*`、`codex-*` | カードのサブスク照会 |
| Kimi For Coding（マネージド OAuth） | `kimi-for-coding`、`k2`、`k3` | そのカードのプラン照会 |
| Claude Pro/Max（`sk-ant-oat…` を持つカード） | `claude-*` | そのアカウントのクォータ |

ルール：

1. **空きを選ぶ**：新しいセッションは既知使用量が**最も低い**アカウント。不明な使用量は既知の後ろに並び、0% 扱いにはしません。
2. **セッション粘着**：会話は開いたアカウントに付きます。
3. **切り替え**：そのアカウントが 401 / 403 / 429 を返す、または最も熱いウィンドウが ≥ 80% で、より空いているアカウントがあるとき。切り替えは**次のリクエスト**です。
4. **固定が優先**：`{slug}/model` はプールを使いません。
5. **Official ChatGPT**：同一リクエスト内のアカウント横断フェイルオーバーはありません。そのホップが失敗したら失敗です。

使用量はカード下部の照会と、成功転送後最大 60 秒に 1 回のバックグラウンド更新です。認証センターにも出ます。トレイは Kimi / Anthropic のクォータ要約を出しません。

## ホストログインカードをルーティングへ載せる

トークンはローカルの account store にだけあり、カード設定には書きません。手順は [1.5](../1-getting-started/1.5-settings.md) と [2.1](../2-providers/2.1-add.md) を見てください。

1. 設定 → **OAuth 認証センター**で Kimi（デバイスコード）または Claude Pro/Max（ブラウザ PKCE / Claude CLI 取り込み）にログイン。
2. プリセット **Kimi For Coding (OAuth)** / **Claude Pro/Max (OAuth)** でカードを追加し、アカウントをバインド。
3. 接管後、セレクタに `{slug}/{model}` が出ます。接頭辞なしの公式系 id は、カードが 2 枚以上ならプールです。

> 空の公式 Claude シードカード（未ログイン、OAuth トークンなし）はプロキシ安全ではありません。認証センターでログインしてからプリセットをバインドしてください。

## よくある使い方

```bash
codex -m "packy/claude-sonnet-4-6"
claude --model "anthropic/kimi/kimi-for-coding"
```

公式 ChatGPT カードが複数あり、新しい会話を空きアカウントへ流すときは、Codex で接頭辞なしの `gpt-5.5` を使います。カードをロックするときだけ slug を付けます。

テストカードをセレクタから隠すには「ルーティングカタログに含める」をオフにし、必要なときだけ `testdev/k2` で呼びます。

カード横断のフェイルオーバーや重み付き分担は、固定 id + アプリ級フェイルオーバーではなく [4.7 Combo](./4.7-combo.md) の `combo/{id}` を使います。

## Codex セレクタのカタログの出所

`~/.codex/cc-switch-model-catalog.json` はテイクオーバー後に書く静的投影であり、上流 `/v1/models` のリアルタイムミラーではありません。Codex カードごとに次を合成します。

1. カードのマッピング表（表示名・コンテキスト長は入力どおり）
2. そのカードの `config.toml` の `model =` と `[model_providers.*].models`
3. Official ChatGPT のローカルシード（`gpt-5.4` / `gpt-5.5` / `gpt-5.6*` など）。chatgpt.com には取りに行きません
4. 前回成功した上流 `GET /v1/models`（`~/.codex/cc-switch-model-discovery.json`）

ループバック（本地プロキシ）と `PROXY_MANAGED` プレースホルダキーでは一覧を取りに行きません。第三者キーは **Codex** タブのカードにだけ載ります。

Codex テイクオーバーの再確認や Combo 保存のあと投影を書き直し、1 回の補完取得を試みます。`/model` に反映するには **Codex を完全終了して再起動**してください。oh-my-codex の `omx setup` は `model_catalog_json` を消し、公式のインライン `models` を書き込み、`name = "OpenAI"` にする場合があります（Codex は Grok に `/responses/compact` を送ります）。テイクオーバー再適用はポインタを戻し、インライン一覧を削り、第三者カードがあるときは `name` を `CC Switch` にしてローカル圧縮に切り替えます。

セッションで `grok/grok-4.6` を選ぶと、プロキシはその選択をスレッドに記憶し、live `config.toml` の `model` を `grok/grok-4.6` に書き込みます。ファイルのデフォルトを読む review / compact / デフォルトモデル要求は `default/gpt-5.6-sol` ではなく Grok に付け替えます。非公式カードへの `/responses/compact` は上流へ送らずローカルで拒否します。Grok に切り替えたら **新しい会話** を開いてください。古い公式 compact 塊は 5xx になることがあります。

## 注意

- OpenCodex / `ocx` を別途起動する必要はありません。
- Combo があるとき、プロバイダー slug を `combo` にしないでください。
- 裸の `gpt-*` は隠しではない。接頭辞なしは上のプール規則です。
- slug を変えても、古いセッション内の `{旧slug}/{model}` は自動では書き換わりません。
