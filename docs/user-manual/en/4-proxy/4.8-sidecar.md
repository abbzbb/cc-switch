# 4.8 Web Search / Vision Sidecar

The sidecar lets a **signed-in** Claude Pro/Max or ChatGPT Official account do two jobs for non-official models:

1. **Web Search**: hosted `web_search` on a non-official, non-Anthropic-OAuth card is rewritten to a function call, executed by the sidecar account, then returned to the original model.
2. **Vision**: when a text-only model receives an image, the sidecar describes it first, then forwards the description.

If nobody is signed in on the chosen backend, both steps stay inert (no rewrite). Official ChatGPT cards and Anthropic OAuth cards do **not** intercept their own hosted search.

> You do not need to install or start OpenCodex. The sidecar runs inside the local proxy. Responses, Claude `/v1/messages`, and Codex `/v1/chat/completions` all use the same loop.

## Before you start

1. In **Settings → OAuth Auth Center**, sign into at least one backend:
   - **Claude Pro/Max**: browser login (`http://localhost:54545/callback`) or import from Claude CLI
   - **ChatGPT Official**: ChatGPT (Codex OAuth) device-code login
2. Start the proxy and take over the app that will send hosted search or images.
3. Open the **Proxy** panel and find **Web Search / Vision Sidecar**.

Web Search and Vision are **off by default**. You can leave the switches on with no backend signed in; requests will not be rewritten. When enabled, the client must also present the inbound capability header written during takeover before the proxy spends Official / Claude quota.

## Settings

Web Search and Vision each have their own switch. Changes save immediately.

| Setting | Meaning |
|---------|---------|
| Web Search / Vision switch | Off = that capability never intervenes |
| Search / vision backend | `Auto`, `Claude Pro/Max`, or `ChatGPT Official` |
| Search / vision model | Optional. Empty uses the backend default |
| Max searches per turn | Cap on sidecar searches in one turn |
| Max descriptions per turn | Cap on image descriptions in one turn |
| Search / vision timeout | Milliseconds. On timeout that sidecar call fails; the original request continues with whatever it has |

**Auto** uses a backend that is signed in and ready. If only one side is signed in, Auto uses that side.

## What gets rewritten

| Situation | Rewritten? |
|-----------|------------|
| Relay / API-key card with hosted `web_search` | Yes — rewritten to a function call |
| Hosted search on an official ChatGPT card | No |
| Hosted search on a Claude Pro/Max OAuth card | No |
| Image on a text-only model | Yes — describe, then forward |
| A model that can already see images | Vision sidecar is not forced |
| Neither backend signed in | No |

## Recipes

**A relay model needs web search, but the vendor has no hosted search**

1. Sign into Claude Pro/Max or ChatGPT Official.
2. Enable Web Search; leave backend on Auto or pick one side.
3. Keep calling the relay card (`{slug}/{model}` or the current provider). When the model requests `web_search`, the proxy hands it to the sidecar.

**A text model needs to read a screenshot**

1. Enable Vision and pick a backend.
2. Send the image to that text model. The sidecar writes a description, then the original model answers.

**Search only, no vision**

Turn Vision off; leave Web Search on.

## Notes

- Sidecar usage draws from the **Claude Pro/Max or ChatGPT subscription**, not the relay card’s balance. Auth Center and the matching official card footer show that usage.
- Official ChatGPT sidecar requests include account and window headers (`chatgpt-account-id`, `session_id`, and related fields) so the Codex backend can route the session. No manual setup.
- Cancelling Claude browser login aborts the local PKCE callback. Do not occupy port `54545` during login.
- An empty official Claude seed card cannot be a sidecar backend. Use an Auth Center login (or a card that already has a token).
