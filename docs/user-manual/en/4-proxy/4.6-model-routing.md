# 4.6 Pick a Model by Provider

Starting in v3.20.0, after **Codex / Claude takeover**, the local proxy merges every participating provider card into the picker. A request that uses a prefixed model id **pins that card** and does not cross-provider failover.

> First start the proxy ([4.1](./4.1-service.md)) and enable Codex and/or Claude takeover ([4.2](./4.2-routing.md)). Without takeover, the CLI still talks to the current provider and will not see the merged catalog.

You will also see a short routing hint on the proxy panel, plus **Routing slug** and **Include in routing catalog** on the add/edit provider form.

## One pass through the flow

1. Add at least one card that participates in routing (API key card, or a managed card bound in Auth Center).
2. Start the proxy and turn on **Codex** and/or **Claude** takeover.
3. Pick a prefixed model id in the CLI (table below).
4. Use `{slug}/{model}` to pin a card. To let official-family models pick an idle account, **omit** the slug prefix.

| App | Id in the picker | Example |
|-----|------------------|---------|
| Codex | `{slug}/{model}` | `codex -m "kimi/k2" "Explain this code"` |
| Claude Code | `anthropic/{slug}/{model}` | `claude --model "anthropic/kimi/k2"` |
| Claude Desktop | `{slug}/{model}` | Choose the merged entry in the model list |

Claude Code takeover enables gateway model discovery (`CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY=1`). `/model` loads `GET /v1/models` from the local proxy. Claude Code drops ids that contain neither `claude` nor `anthropic`, so catalog entries are `anthropic/{slug}/{model}`. The haiku / sonnet / opus / fable role aliases are unchanged.

Claude Desktop’s `/claude-desktop/v1/models` still returns the merged `slug/model` list. That listing stays separate from Claude Code’s `anthropic/...` catalog.

## Pin a card: `{slug}/{model}`

The canonical id is `{routing_slug}/{upstream_model}`.

- A request with that id always hits the matching card and injects that card’s credentials.
- `main/gpt-5.5` still pins the `main` card and injects that card’s token even if Codex is currently signed into a different ChatGPT account.
- A pinned request does **not** use app-level cross-card failover.

### Where the slug comes from

On the add/edit provider form:

- Leave **Routing slug** empty to use the provider `id`, or a name-derived slug.
- Save an override (`kimi`, `deepseek`, …) so a later rename does not send old sessions to another card.
- The card shows a “routing {slug}” badge.

**Include in routing catalog**:

- On (default): the card’s models appear in the merged Codex / Claude Desktop picker.
- Off: the card is hidden from the picker, but a slug prefix still works.

You can also tick cards under **Configs in the routing catalog** on the proxy panel, without opening each edit form. The platform switch (Codex / Claude / …) only takes over that app’s live config; it does not choose which cards enter the picker. Gemini / Grok have no merged picker — they still use the current config plus the failover queue.

The form previews a few ids that will be written into the catalog.

### `/` inside an upstream model id

Inner `/` characters become `-` in the catalog (`org/model` → `kimi/org-model`). Both spellings are accepted on the request.

### The first segment is not a configured slug

Example: Claude Desktop’s built-in `anthropic/claude-sonnet-5`. If `anthropic` is not a card’s routing slug, the proxy falls through to the current provider instead of returning 400.

## Unprefixed: current provider, or an account pool

A model name with no slug prefix keeps the old behavior: current provider, plus the app-level failover queue if that switch is on. Claude role aliases still work.

These official families use an **account pool** when the same app has two or more cards of that family and the request is unprefixed:

| Family | Unprefixed ids that enter the pool | Utilization source |
|--------|------------------------------------|--------------------|
| ChatGPT Official (Codex official cards) | `gpt-*`, `o1` / `o3` / `o4*`, `codex-*` | Card subscription query |
| Kimi For Coding (managed OAuth cards) | `kimi-for-coding`, `k2`, `k3` | That card’s plan query |
| Claude Pro/Max (cards that store `sk-ant-oat…`) | `claude-*` | That account’s quota query |

Pool rules:

1. **Pick idle**: a new session uses the account with the **lowest known** utilization. Unknown utilization ranks after a known value, never as 0%.
2. **Sticky session**: the conversation stays on the account that opened it.
3. **When it moves**: 401 / 403 / 429 from that account, or the hottest window is ≥ 80% and a more idle account exists. The switch happens on the **next** request, not mid-request.
4. **Pin wins**: `{slug}/model` still pins and does not use the pool.
5. **Official ChatGPT**: no same-request cross-account failover. If that hop fails, the hop fails.

Utilization comes from the card footer and from a background refresh at most once per 60 seconds after a successful forward. Auth Center shows the same per-account usage. The tray does **not** show Kimi / Anthropic quota summaries.

## Hooking a hosted-login card into routing

Tokens stay in the local account store and are **not** written into the card. Full steps: [1.5 Personalization → OAuth Auth Center](../1-getting-started/1.5-settings.md#oauth-auth-center-beta) and [2.1 Add Provider → Managed OAuth providers](../2-providers/2.1-add.md#managed-oauth-providers-kimi--claude-promax).

1. Settings → **OAuth Auth Center**: sign into Kimi (device code) or Claude Pro/Max (browser PKCE / Claude CLI import).
2. Add a provider with **Kimi For Coding (OAuth)** or **Claude Pro/Max (OAuth)** and bind the account.
3. After takeover, the picker shows `{slug}/{model}`; unprefixed official-family ids use the pool when you have two or more cards.

> An empty official Claude seed card (no completed login, no OAuth token) is **not** proxy-safe. Sign in via Auth Center, then bind the preset.

## Common recipes

**Force one relay card’s model**

```bash
codex -m "packy/claude-sonnet-4-6"
claude --model "anthropic/kimi/kimi-for-coding"
```

**Several official ChatGPT cards, new chats go to the idle account**

Keep using unprefixed `gpt-5.5` in Codex. Add a slug only when you must lock one card.

**Hide a test card from the picker**

Edit the card, turn off **Include in routing catalog**, and call `testdev/k2` when you need it.

**Failover or weighted sharing across cards**

Do not combine a pinned id with app-level failover. Use `combo/{id}` in [4.7 Combo virtual models](./4.7-combo.md).

## Where the Codex picker list comes from

`~/.codex/cc-switch-model-catalog.json` is a static projection written after takeover. It is **not** a live mirror of upstream `/v1/models`. Each Codex card is the union of:

1. The card’s mapping table (keeps the display names and context windows you entered)
2. `model =` and `[model_providers.*].models` in that card’s `config.toml`
3. A local Official ChatGPT seed (`gpt-5.4` / `gpt-5.5` / `gpt-5.6*`, …) — no live chatgpt.com fetch
4. The last successful upstream `GET /v1/models` (stored in `~/.codex/cc-switch-model-discovery.json`)

Loopback URLs (the local proxy) and `PROXY_MANAGED` placeholder keys are never used to fetch lists. Third-party keys only appear if the card lives on the **Codex** tab.

Opening or re-confirming Codex takeover, or saving a Combo, rewrites the projection and tries one enrich fetch. **Fully quit and restart Codex** so `/model` reloads the file. oh-my-codex `omx setup` may overwrite `model_catalog_json`; keep it pointed at `cc-switch-model-catalog.json`.

## Notes

- You do not need to start OpenCodex / `ocx`. The local proxy does the routing.
- Do not name a provider slug `combo` if any Combo exists. See [4.7](./4.7-combo.md).
- Bare `gpt-*` ids stay visible. Unprefixed requests follow the pool rules above.
- Changing a slug does not rewrite old sessions that already stored `{old-slug}/{model}`.
